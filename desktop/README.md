# Windows 客户端

适用于 Windows 10/11 x64。客户端连接现有周报网站，服务器仍通过 Docker 部署。

## 安装与使用

1. 运行 `WeeklyReport-Setup-1.0.0-x64.exe`，选择安装目录。安装器创建桌面和开始菜单快捷方式。
2. 打开“周报填写检查”，填写测试网站 `https://dev.images.city`（也可填写自己的 HTTPS 域名）。网站须部署本次 `develop` 的服务端与前端更新。
3. 使用原有帐号登录。若希望重启应用、会话过期后继续接收通知，勾选登录页的“自动登录”。客户端不额外保存帐号密码。
4. 在首页打开“允许通知”。成功后本机显示“消息推送启动成功！”。重复刷新不会再发；关闭后重新开启会再发一次。
5. 关闭主窗口后留在系统托盘，每 15 秒读取新通知；在托盘右键选择“退出”才完全结束。电脑休眠、断网或退出应用期间不能实时接收；恢复连接后补读仍在一小时有效期内的消息。
6. 托盘菜单可重新打开页面、更换网站或选择开机启动。开机启动默认关闭。点击业务通知会打开应用，并在跳转文档前确认，以免丢失当前编辑。

每个文档仍只允许一条主推送，可取消。推送正文为实际渲染的邮件标题。客户端开关仅控制本机，不改变邮件发送或其他设备的订阅。退出帐号会关闭本机通知，重新登录后需手动开启。

首次开启从最新游标开始，不补发此前通知。传输和系统显示不保证严格恰好一次；进程在显示后、保存游标前崩溃，可能重复显示该条消息。

## 各平台行为

| 平台 | 接收方式 | 后台条件 |
| --- | --- | --- |
| Windows 客户端 | 主进程读取服务器通知并显示 Windows 系统通知 | 应用在托盘运行；无需打开浏览器 |
| 普通桌面网页 | 浏览器系统通知 | 至少保持一个页面打开，后台可能受浏览器节流 |
| iPhone 主屏幕应用 | Apple Web Push | iOS 16.4+、有效 HTTPS、服务器启用 Apple 推送、用户允许通知 |
| iPhone 普通网页 | 页内提醒 | 页面打开可见；应添加到主屏幕以使用后台推送 |
| Android 网页或现有 WebView 壳 | 支持通知 API 时使用系统通知，否则页内提醒 | 保持页面运行；没有接入国内厂商的进程关闭后推送 |

不使用 Google/FCM 或第三方聚合推送。本次不生成 Android APK；国内厂商后台推送需要对应应用与厂商凭据，不能把普通 WebView 页内提醒当作系统后台推送。

## 构建

在 Windows 安装 Node.js 22 后：

```powershell
cd desktop
npm ci
npm test
npm run dist:win
```

安装程序位于 `desktop/dist/`。`Windows installer` GitHub Actions 工作流在 develop 的客户端/应用修改后构建、静默安装、验证开始菜单快捷方式，并运行已安装程序的登录、托盘后台通知与退出帐号测试。产物 `WeeklyReport-Windows-x64` 包含 EXE、SHA256 校验文件和验证截图，有效期 30 天。可通过 Actions → Windows installer → Run workflow 重新构建。

当前安装包未做付费代码签名，Windows 可能显示“未知发布者”或 SmartScreen 提示。通知需允许 Windows 设置中的应用通知；专注模式可影响横幅显示。自动化验证模拟了操作系统通知显示，真实通知中心、锁屏和专注模式需在使用者电脑验证。

## 本地验证

```bash
python -m pip install -r requirements.txt
npm ci --prefix desktop
npm test --prefix desktop
node tests/desktop_smoke.cjs
```

Linux 图形测试使用 `xvfb-run -a node tests/desktop_smoke.cjs`。测试使用本地假 SMTP 服务，不发送真实邮件或远程推送。

网页运行在 Electron 沙箱中，关闭 Node 集成，桥接接口限制为当前主窗口、顶层框架和已配置来源。设置页面使用独立接口；禁止远程页面打开新窗口、嵌入 WebView、下载文件或跳转其他来源。不绕过 HTTPS 证书检查。不同服务地址使用隔离的会话分区。通知偏好只保存用户 ID、游标和开关，不保存密码或令牌；登录 Cookie 由 Chromium 会话管理。
